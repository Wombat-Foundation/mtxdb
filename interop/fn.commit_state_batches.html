pub fn commit_state_batches<'a>(
    db: &Database,
    nodes: impl IntoIterator<Item = ([u8; 16], [u8; 16], &'a [u8])>,
    roots: impl IntoIterator<Item = ([u8; 16], [u8; 16], &'a [u8])>,
    batch_bytes: usize,
) -> Result<usize, StorageError>
Expand description

Stage HAMT nodes, then roots, into bounded transactions of at most batch_bytes charged bytes, committing each before the next begins.

All supplied nodes are committed before any root. The caller must supply every node needed by the roots that is not already stored; references and content hashes are not validated. An interrupted run can leave unreferenced nodes and already-committed roots. nodes and roots are (collection, node id, bytes) stored in STATE_POOL; the caller derives ids with the functions above. The budget includes payload bytes plus crate::journal::TXN_STAGE_PUT_OVERHEAD_BYTES per record. Returns the number of transactions committed, or zero if both inputs are empty.

§Errors

Returns the first staging or commit error; earlier batches stay committed. Returns StorageError::Io with std::io::ErrorKind::InvalidInput for a zero or over-engine-limit budget, staging-size overflow, or a single record that cannot fit in the requested budget.

This is not an atomic migration across batches. The caller must publish its import-complete marker only after this function succeeds; on failure, already-committed nodes/roots remain visible, with nodes always committed before roots.
