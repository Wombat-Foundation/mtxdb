Shared on-disk layouts for the server/importer boundary: verdicts, signing keys, and the import marker. Shared on-disk layouts for the server/importer boundary.

mtxdb is the only store for events, verdicts, signing keys and state. A server writes those records through its adapters; an mtxdb import batch writes the same records from an export file. Both must agree on every byte, or a room that imported cleanly reads as empty after a restart. This module owns that agreement: the encodings, the collection and node derivations, and the data-format version the import marker vouches for.

Identity note: room collection ids use mtxdb’s BLAKE3 group derivation plus a namespace bias. Other interop ids use BLAKE3-128; where multiple logical ids share a collection, their derivation uses a NUL-separated domain tag. Event record ids deliberately match the Matrix template’s BLAKE3-128 of the complete event id.

State HAMT construction and state derivation are deliberately not implemented here. The server and offline importer must use the same rezzy HAMT builder and encoding; this module owns only stable mtxdb collection/node identities and bounded publication helpers.
