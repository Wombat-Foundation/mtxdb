Expand description

Wall-clock breakdown of one sync — the append-path sync() (dirty-scoped flush/fsync) or the full sync_all — by phase. The pack phases come from ShardPool::last_sync_split (which measures the flush and fsync legs separately) and the metadata phases from the sync method itself.

Fields§

§failed: bool

Whether this barrier returned an error after collecting its partial timings.

§pack_flush: Duration

Writing buffered frames out to the pack files.

§pack_fsync: Duration

fsync’ing the pack files.

§sidecar: Duration

Writing the shard→collection metadata sidecar.

§delta_log: Duration

Persisting the index checkpoint (complete rewrite) or appending the incremental delta log instead (ZERO on the path not taken; the appended case is measured when a dirty sync() can continue an existing log).

§checkpoint: Duration

Persisting the index checkpoint.

§reclaim: Duration

Coverage reporting and WAL reclaim performed by a coverage-step delta batch (not by a checkpoint tail, whose phases are in CheckpointBreakdown). This is the shared-segment rewrite and fsync that shrinks the journal once every pool has reported.

§reclaim_boundary: Duration

Breakdown of Self::reclaim: deciding the shared-reclaim boundary (directory lookup, or a scan when the directory could not be trusted).

§reclaim_copy: Duration

Breakdown of Self::reclaim: reading and re-encoding the retained suffix into the rebuilt segment.

§reclaim_fsync: Duration

Breakdown of Self::reclaim: writing, fsyncing and renaming the rebuilt segment into place. The likely disk cost.

§reclaim_retained_bytes: u64

Bytes the last reclaim rewrite moved and fsynced: the retained suffix. This is what reclaim_copy/reclaim_fsync scale with.

§reclaim_blocked_by: Option<ShardType>

The pool whose missing coverage stopped the last reclaim cut, so the suffix could not be dropped sooner. None when an untagged frame stopped it or the caller could not attribute it. Diagnostics only.

§remediation: Duration

Time spent in remediate_lagging_pools: in the non-background path this force-checkpoints a pool holding the shared WAL back, and the caller waits for it. Kept separate from Self::reclaim so a phase breakdown can tell a coverage-step reclaim from a remediation checkpoint (whose own journal wait would otherwise be miscounted as reclaim).

§wal: Duration

Committing the pending write-ahead journal group (one sequential fsync). Zero when no journal is configured.

§journal_lock_wait: Duration

Time spent waiting for the journal’s single-writer mutex.

§journal_fsync: Duration

Time spent making the journal file durable.

§journal_sync_calls: u64

Number of journal sync calls represented by this operation.

§journal_records: u64

Records appended to the journal by this operation.

§journal_waiters: u64

Whether this operation waited for the journal mutex.

§journal_coalesced: u64

Whether this operation was already covered by another sync.

§journal_in_flight: u64

Number of journal sync callers active when this operation entered.

§dirty_lock_wait: Duration

Time spent waiting for the shard pool’s dirty-set lock in this barrier.

§pending_publish_age: Duration

Age of the oldest unpublished write when this barrier began.

§total: Duration

Total wall time of the sync_all call.
