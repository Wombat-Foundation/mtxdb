Expand description

Wall-clock breakdown of one PackfileStorage open, by phase. Measured with a handful of Instant::now() deltas on the open path only, so recording these doesn’t perturb the numbers they report.

The per-phase fields partition the synchronous open work; see the struct-level timing doc for what each phase covers. On the checkpoint path full_scan is zero; on the fallback path checkpoint_decode and fingerprint still reflect the attempt that failed validation (e.g. a missing or stale checkpoint) before the scan had to run.

§shard_open: Duration

Total time spent opening the shard pool, including discovery, locking, packfile recovery, and metadata restoration.

§shard_discovery: Duration

Directory and pack-file discovery.

§writer_lock: Duration

Acquiring the writable pool lock.

§packfile_recovery: Duration

Cumulative packfile recovery/validation scan time in the shard pool.

§packfile_recovery_calls: u64

Number of packfiles passed through recovery/validation.

§packfile_open: Duration

Time spent opening packfiles and validating their headers.

§packfile_open_calls: u64

Number of packfiles successfully opened.

§metadata_restore: Duration

Restoring pool metadata and persisted shard statistics.

§pool_meta_restore: Duration

Restoring pool.meta header and reading next pack ID.

§persisted_stats_restore: Duration

Reading and restoring persisted snapshot counters from shard_stats.bin.

§store_meta_write: Duration

Writing store.meta version marker via best-effort atomic write (fresh pool only; ZERO on existing pool).

§pool_meta_persist: Duration

Persisting pool.meta reservation and syncing file contents (fresh pool only; ZERO on existing pool).

§initial_pack_create: Duration

Creating the initial packfile atomically, writing its header, syncing, renaming, and performing the final directory sync (fresh pool only; ZERO on existing pool).

§metadata_unattributed: Duration

Unattributed time inside the metadata_restore span.

§shard_open_unattributed: Duration

Shard-open time not covered by the named shard phases.

§metadata_load: Duration

Reading the collection-order and deleted-collections sidecars.

§checkpoint_decode: Duration

Reading + decoding the persisted index checkpoint.

§fingerprint: Duration

Recomputing the live (pack_id, file_len) set’s fingerprint.

§index_materialization: Duration

Deserializing checkpoint index blobs into live collections (checkpoint path) or building per-collection indexes from scanned records (fallback path). On the checkpoint path this includes replaying any fingerprint/generation-gated delta-log frames on top of the raw slots.

§delta_replay: Duration

Reading the delta log, validating its gates, and applying frames to each affected collection (checkpoint path only; ZERO when there is no committed log to replay).

§full_scan: Duration

The full packfile scan + torn-tail recovery pass (fallback only).

§total: Duration

Total synchronous wall time of the open.

§path: OpenPath

Which index-loading path was taken.

§bookkeeping_source: BookkeepingSource

Where per-shard counts and home-shard assignment came from (checkpoint path only; the fallback path builds them from the scan).
