Struct TxnStage

pub struct TxnStage { /* private fields */ }
Expand description

Transaction-local mutation buffer used by crate::database::DatabaseTransaction.

Journal entries for a SQL transaction are buffered here and published from its post-commit callback. Call Self::discard from the transaction’s error callback; that is required because Synapse retains after-callbacks across retry attempts.

§Storage boundary

Self::discard drops only buffered mutations. The database transaction applies them to packs and indexes only after its caller declares commit, then publishes the resulting shared-WAL group.

pub fn lookup_many( &self, pool: ShardType, collection_id: &[u8; 16], node_ids: &[[u8; 16]], ) -> Vec<StagedLookup>

Look several records up in the mutations staged for pool, in the order of node_ids, taking the stage lock once and scanning the staged mutations once however many records are asked for.

This is what lets a transaction read its own uncommitted writes. The staged mutations are in append order, so the newest one that names a record wins. A staged DeleteCollection for the record’s collection hides everything older, both earlier staged puts and whatever the live pool holds, while a put staged after it is newer and is seen. Only an active stage answers: once the stage is discarded, or publication has begun, every record is Absent and the caller reads the live store, which by then serves the group through the transaction overlay.

The single pass keeps the newest put position for each wanted record and the position of the last delete for the collection, so the cost is the staged mutations plus the records asked for, not their product. Payloads are cloned only for records that resolve to a put.

pub fn stage_remove_record( &self, pool: ShardType, collection_id: [u8; 16], node_id: [u8; 16], ) -> Result<()>

Add a per-record removal to this attempt.

The caller must establish that the key is live (or was put earlier in this stage) before staging the removal. This keeps an absent-key removal from creating a journal entry or advancing collection clocks.

§Errors

Returns an error if the stage is inactive or its size limit would be exceeded.

pub fn stage_removals_normalized( &self, pool: ShardType, collection_id: [u8; 16], pending: &[([u8; 16], u64)], live_ids: &[[u8; 16]], ) -> Result<()>

Stage a normalized removal batch all-or-nothing: drop this stage’s earlier mutations for pending, stage removal markers for live_ids, and record each pending key’s version precondition. The budget is checked before anything changes, so an Err leaves the stage exactly as it was.

§Errors

pub fn publish( &self, coordinators: [Option<&JournalCoordinator>; 4], ) -> Result<()>

Append staged pool groups in dependency order: edges, event-DAG, then state. Does not fsync; the ordinary coalesced sync remains the durability boundary. Repeated calls are safe, including after a partial error.

§Errors

Returns an error if a staged pool has no coordinator or its journal cannot append the group’s complete framing and trailer.
