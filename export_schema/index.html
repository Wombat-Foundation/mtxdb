Wire schema of the mtxdb-export/v1 interchange.

A homeserver writes a room (or its signing keys) as JSONL; mtxdb import reads it. Both sides must spell every record tag and field the same way and agree on what each verdict code number means, so those live here once. The module is pure: names, numbers and tag conversions, no JSON library and no I/O. The kind of a server_keys record is crate::interop::KeyRecordKind::as_str.

Each line is one JSON object tagged by field::T:

  1. tag::HEADER: field::FORMAT, field::SERVER, field::ROOM_ID.
  2. tag::EVENT: the event’s identity, edges, flags, verdict codes and PDU.
  3. tag::END: field::EVENTS, the number of event records. A file without it was truncated.

A keys export is tag::SERVER_KEYS records only.
