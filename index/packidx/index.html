Module packidx 

Source
Expand description

Immutable, per-pack sorted locator-index format.

Packs remain authoritative. The sidecar stores (collection_id, logical_id) -> byte_offset and can be rebuilt by scanning its pack. This module defines the format and I/O primitives; pack sealing and store-open integration are separate work.

Version 1 is little-endian:

[64-byte header]
[collection directory: 20 bytes per collection]
[collection sections in collection-id order]

The MTXIDX01 magic identifies the version. The header CRC field is zeroed while calculating CRC32 over the complete file. Each directory entry is a 16-byte collection id followed by a u32 entry count. Its section starts immediately after the previous section and contains cumulative fanout[256], sorted 16-byte logical ids, then parallel u32 offsets. Duplicate (collection_id, logical_id) inputs keep the greatest offset.

PackIndex::build sorts one flat input vector and is intended for in-memory construction. It does not implement external sorting; a bounded memory builder must merge sorted spill runs before encoding.
